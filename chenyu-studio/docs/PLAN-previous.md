# 严晨宇个人网站：设计与实现方案

状态：方案已确认并进入本地实现。用户最新要求：仅电脑端 Web，跳过手机适配、验收与预览。以下涉及移动端与预览的原计划保留为后续事项。视觉依据为 concepts/studio-lineart-v2.png；实际相机已升至眼睛附近。

## 已确认的方向

- 白底、黑色漫画线稿；保留黑发、透明框眼镜、白色卫衣与轻松的人物姿态。
- 人物坐在桌前，背向桌搭、面向前方摄像机；桌子和屏幕位于人物身后。
- 桌搭遵循原始照片：左侧支架笔记本、中央显示器及屏幕灯、下方平板与白色键盘、触控板和鼠标、手机、右侧单台 PS5、左右音箱。
- 将相机及三脚架整体升高，使镜头接近坐姿人物的眼睛高度，保持镜头对准人物，并避免遮挡人物脸部。
- 后续履历、作品、文章和联系方式由用户提供，不编造真实经历或项目。

## 产品定位与访客路径

暂按兼顾个人表达与作品展示的个人网站规划，受众为想了解本人、作品或建立联系的访客；具体职业定位待用户内容补充后确定。

首页让访客先认识人物及其工作环境，再进入作品、文字、关于或联系。场景物件提供探索式入口，顶部文字导航始终提供相同目标；无需猜测图中哪里能点击。常规滚动可浏览首页摘要，独立内容页可直接分享和通过浏览器前进、后退。

## UI 与布局

主视觉为大幅线稿工作室，直接融入白色页面。墨黑用于文字、头发与线条；浅灰仅用于分隔与次级表面。首版保持黑白，无彩色渐变。正文用清晰的中文无衬线字体，标题适度放大，保留宽松留白；手绘表达集中在插画和少量标注，不用于长正文。

桌面首页：顶部姓名与四项导航；一小段欢迎语；占据首屏主体的工作室；底部轻量探索提示与向下浏览入口。正文依次为精选作品、最近文字、关于摘要与联系。内容页延续留白和字体，但以文章、图像和项目说明为主体。

移动端：先显示简短介绍和完整场景，再以清晰的文字入口继续浏览。核心物件不强行裁切，场景可点开查看大图。触控入口至少 44px，不依赖悬停。长内容采用单栏；动画降级为淡入、状态切换。

## 场景交互

| 元素 | 操作反馈 | 导向 |
|---|---|---|
| 人物 | 悬停或键盘聚焦显示“关于我”；点击时短暂回应 | 关于页面 |
| 主显示器 | 屏幕出现作品预览，显示“看看作品” | 作品列表 |
| 笔记本 | 屏幕出现简洁文字预览 | 文章列表 |
| 桌上的手机 | 显示“联系我” | 首页联系区域 |
| 三脚架相机 | 点击进入局部取景构图，显示可见的退出按钮 | 轻量趣味体验，不调用设备摄像头 |
| 摄影灯 | 点击切换插画中的灯光线条与开关状态 | 场景反馈，保持黑白视觉 |

热点使用真实链接或按钮，不依赖裸坐标点击区域。悬停、聚焦、触摸均有明确反馈；动画中允许取消或返回。相机取景态可按 Escape 退出，退出后焦点回到触发按钮；相机效果仅模拟画面，不录制访客。

首次进入：内容立即可读，场景用一次短暂淡入完成呈现。人物可有低频眨眼和轻微呼吸，鼠标移动仅带来很小的分层位移，避免整幅画持续摇晃。按下反馈约 120–180ms，标签约 180–240ms，路由或取景转场约 350–500ms；实现时按实际画面调整。支持系统减少动态效果设置，离开视口或标签页失焦时暂停持续动画。

## 页面范围与内容

- `/`：工作室、精选作品摘要、文字摘要、关于摘要、联系。
- `/work` 与 `/work/[slug]`：作品目录与独立案例，包含背景、本人职责、过程、成果、图像、相关链接及下一篇。
- `/notes` 与 `/notes/[slug]`：文章目录与阅读页，后续文章按日期管理。
- `/about`：自我介绍、经历、兴趣及桌搭说明；只呈现用户提供的内容。
- 联系区：真实邮箱复制、邮件链接和社交链接。未提供真实地址前不出现伪造联系方式或可提交但无处理端的表单。
- 定制 404、分享标题与描述、站点地图、图片替代文字与基础搜索引擎元数据。

私人预览中可显示清楚标注的占位内容。对外版本隐藏空列表和对应场景入口；补入真实内容后开启。不会用虚构项目填满页面。首版不需要账号、数据库或管理后台。

## 推荐技术

- Astro + TypeScript：静态生成内容页和路由。内容主体直接输出 HTML，利于阅读、分享和首屏展示。
- React islands：仅工作室、筛选或需要状态的局部区域加载交互代码。
- Motion for React + CSS：处理场景分层、弹性反馈与进出场；基础悬停、焦点和颜色变化使用 CSS。
- Astro View Transitions：用于列表到详情和返回时的轻量视觉连续性，保留普通导航回退，测试历史记录、焦点及减少动态效果行为。
- 透明 WebP/PNG 图层 + SVG/HTML 控件：承载人物、桌搭、相机和灯；热点为可访问的 HTML 元素，SVG 用于简洁的取景框、图标等几何内容。
- Markdown/内容集合：保存文章、作品详情；站点信息、社交链接与场景配置集中管理。以后可接内容管理服务。
- 静态构建输出：计划发布到已建立的 Sites 私人站点供预览；以后按用户要求绑定域名或调整访问权限，发布配置以平台实际能力为准。

选择分层 2.5D 是为了忠实保留获批线稿。第一版不提供自由环绕房间或三维换机位。若后续需要真实转身、任意旋转视角或复杂肢体表演，需要额外的角色绑定、模型或 Live2D/Rive 制作；不能从当前一张 PNG 直接得到。

- https://docs.astro.build/en/concepts/islands/
- https://docs.astro.build/en/guides/view-transitions/
- https://motion.dev/docs/react

## 素材实现的关键步骤

先抬高相机定稿，再分别准备干净背景、桌搭、人物、相机与三脚架、灯与灯架、可替换屏幕内容。补齐各物件后方遮挡的区域，使轻微位移不露洞；固定同一套构图与比例，避免多次生成导致风格漂移。

人物眨眼需同一角色的睁眼/闭眼状态或可控的局部绘制；身体只做幅度很小的呼吸。不以扭曲整张 PNG 代替人物动作。图层拼合与原稿比较，边缘、缩放和视角通过后再接动画。如果分层损伤线条，优先保留完整插画并实现屏幕、热点与取景反馈，单独说明人物动画未完成。

## 实施顺序与验收

1. 视觉定稿：相机升高，桌搭位置保持；给出桌面 1440px 与手机 390px 首页设计，锁定场景比例及导航位置。
2. 场景制作：完成分层、热点、屏幕状态、相机取景及灯光反馈；验证键盘与触摸交互。
3. 网站框架：实现首页、作品与文章列表/详情、关于、联系与 404；集中管理待补内容。
4. 内容接入：加入用户提供的简介、作品、文章和真实联系信息，检查图片与链接。
5. 验收与交付：覆盖 390/768/1440px，检查无横向溢出、热点对齐、导航和返回、加载失败回退、复制失败反馈、减少动态效果、移动端首屏与图片清晰度，构建通过后提供私人预览。

性能目标为移动端 LCP 不高于 2.5s、CLS 不高于 0.1，在约定测试环境中测量并报告实际结果；这些是目标而非当前成绩。首屏图优先加载，其他图按需加载；中文字体按字符子集处理，避免无必要的全字库传输。
